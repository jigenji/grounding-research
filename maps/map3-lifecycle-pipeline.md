## この地図から読み取れること

### 1. 「誰も全ステージをカバーしない」

どの手法も単独ではライフサイクル全体をカバーできない。これがハイブリッドアプローチの必然性を示す。

**典型的な組み合わせ例:**
```
オントロジー(②) + ナレッジグラフ(②③④) + RAG(③④⑤) + ガードレール(⑦) + メモリ(⑤⑧)
= フルスタック・グラウンディング
```

### 2. 手法の「専門領域」

- **上流専門（①②）**: オントロジー、タクソノミー、デジタルツイン — 知識の定義・構造化に特化
- **中流専門（③④⑤）**: RAG、エンベディング検索 — 知識の格納・検索・注入に特化
- **下流専門（⑥⑦）**: ガードレール、スキーマ検証 — 出力の制御・品質保証に特化
- **横断型（①〜⑧）**: ナレッジグラフ、メモリシステム — 複数ステージにまたがる

### 3. 上流投資の重要性

ステージ②（構造化）に投資する手法が最も多い。ここでの品質がパイプライン全体の品質を決定する（Garbage In, Garbage Out）。

### 4. フィードバックループの弱さ

ステージ⑧をカバーする手法が比較的少ない。多くのシステムが「使い捨て」のパイプラインになりがちで、継続的改善の仕組みが弱い。メモリシステムとFeature Storeがこのギャップを埋める。

### 5. エージェンティックAI = パイプラインのオーケストレーター

エージェンティックAIは特定のステージに属さず、**パイプライン全体をオーケストレーション**する存在。
どのステージをいつ・どの順序で実行するかを動的に決定する。

```
┌────────────────────────────────────────────────────┐
│             エージェンティックAI                       │
│        (パイプライン全体のオーケストレーター)            │
│                                                      │
│   計画 → ツール選択 → 実行 → 評価 → 再計画            │
│     │        │         │       │       │            │
│     ▼        ▼         ▼       ▼       ▼            │
│   ①②③    ④⑤⑥      ⑥⑦     ⑧     ①〜⑧           │
│   知識準備   検索・生成   出力制御  学習   再実行        │
│                                                      │
└────────────────────────────────────────────────────┘
```
