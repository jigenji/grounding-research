# 地図2: 知識の抽象度 × 応答レイテンシ（知識の鮮度）

> **横軸 (X)**: 応答レイテンシ / 知識の鮮度 — 左が遅い（事前準備型、静的）、右が速い（リアルタイム、動的）
> **縦軸 (Y)**: 知識の抽象度 — 下が具体的・インスタンスレベル、上が抽象的・スキーマ/概念レベル

この地図は「AIがどの抽象レベルの知識を、どのタイミングで取得するか」を可視化する。

## この地図から読み取れること

### 1. 「設計時 vs 実行時」の二層構造

グラウンディング手法は大きく2つの時間軸で機能する:

- **設計時（Design Time）**: オントロジー、ルール、スキーマ等を人間が事前に定義。変更は慎重かつ低頻度
- **実行時（Runtime）**: RAG、ツール利用、センサー入力等でリアルタイムに知識を取得。高頻度に変化

効果的なAIシステムは**両方の層を組み合わせる**。設計時知識が「枠組み」を、実行時知識が「具体的事実」を提供する。

### 2. 抽象度と鮮度のトレードオフ

- **左上（高抽象・低鮮度）**: 安定した概念スキーマ。変わりにくいが更新も困難
- **右下（低抽象・高鮮度）**: 具体的な最新データ。リアルタイムだが文脈なしには意味が不明

**最適なグラウンディング**: この対角線上の両端を結ぶ。
例: オントロジー（概念定義）+ RAG（最新データ）= OG-RAG

### 3. ガードレールの特異な位置

ガードレール/Constitutional AIは右上に位置する。これは:
- **抽象的（概念レベル）**: 「有害な出力を避ける」等の高レベル原則
- **リアルタイム適用**: 毎回の出力に対して即座に適用

つまり、設計時に定義された抽象原則を実行時にリアルタイム適用する**唯一の手法**。

### 4. 知識の「重力」

- 上方の手法は**知識の「骨格」**を提供する（スキーマ、概念体系、ルール）
- 下方の手法は**知識の「肉付け」**を提供する（データ、事実、センサー値）
- 骨格なき肉付けは無秩序（ハルシネーション）、肉付けなき骨格は空虚（実用性欠如）

### 5. ユースケースとの対応

| ゾーン | 典型的なユースケース |
|-------|-------------------|
| 左上（設計時・高抽象） | ドメインモデリング、規制コンプライアンス、知識基盤構築 |
| 中央（蓄積・中抽象） | エンタープライズナレッジベース、内部検索 |
| 右下（実行時・低抽象） | リアルタイム意思決定、IoT/製造、カスタマーサポート |
| 右上（実行時・高抽象） | AIの安全性保証、出力品質管理 |
