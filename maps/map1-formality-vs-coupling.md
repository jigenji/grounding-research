## 象限の詳細解説

### 象限I: デジタル統治（高形式性 × 高結合度）— 右上

**特徴**: 意味が厳密に定義され、かつシステムに深く統合されている。最も制御されたグラウンディング。

**含まれる手法**: デジタルツイン + 物理法則、ツール利用/MCP、Graph RAG、ガードレール/Constitutional AI

**ユースケース**:
- ミッションクリティカルなシステム（製造制御、金融取引）
- リアルタイムの意思決定支援
- 規制遵守が必須の領域（医療、金融）

**トレードオフ**: 導入・維持コストが最も高い。柔軟性が低く、変更に伴うリスクが大きい。

---

### 象限II: 知識の宝庫（高形式性 × 低結合度）— 左上

**特徴**: 形式的に豊かな知識表現だが、特定のシステムに密結合していない。知識基盤として共有・再利用可能。

**含まれる手法**: OWLオントロジー、形式論理/ルールエンジン、ナレッジグラフ

**ユースケース**:
- ドメイン知識のモデリング（医療、法律、科学）
- 組織横断的な知識共有基盤
- 推論・整合性検証

**トレードオフ**: 構築に専門知識（オントロジスト等）が必要。スケーラビリティに課題。実運用への橋渡しが別途必要。

---

### 象限III: 軽量スタート（低形式性 × 低結合度）— 左下

**特徴**: 手軽に始められ、維持コストが最低。しかし形式性・ガバナンスが弱くスケール限界がある。

**含まれる手法**: 平ドキュメント、構造化プロンプティング、ファインチューニング/RLHF

**ユースケース**:
- プロトタイプ、PoC
- 小規模プロジェクト（CLAUDE.md等）
- 個人利用・実験的用途

**トレードオフ**: スケールしない。品質の保証・監査が困難。知識が古くなっても気づきにくい。

---

### 象限IV: ブラックボックス接続（低形式性 × 高結合度）— 右下

**特徴**: システムに深く統合されているが、意味表現が暗黙的・不透明。

**含まれる手法**: マルチモーダルグラウンディング、Feature Store（一部）

**ユースケース**:
- リアルタイムセンサーデータの処理
- 大規模MLパイプライン
- パフォーマンス最優先の場面

**トレードオフ**: 説明可能性が低い。デバッグ・監査が困難。障害時の原因特定が複雑。

## 進化の方向性（矢印）

```
  形式性
  (高)
   │          ┌──────────────────────────┐
   │          │ 知識の宝庫  →  デジタル統治 │  ← 多くの手法がここを目指す
   │          └──────────────────────────┘
   │                 ↑                ↑
   │                 │                │
   │          ┌──────┘    ┌──────────┘
   │          │           │
   │   軽量スタート   ブラックボックス接続
   │
   └────────────────────────────────────→ 結合度(高)
```

**主要な進化トレンド:**
1. **Naive RAG → Advanced RAG → Graph RAG**: 形式性と結合度の両方が段階的に上昇
2. **平ドキュメント → RAG → エージェンティックAI**: 左下から右上への対角移動
3. **ナレッジグラフ + RAG = Graph RAG**: 象限IIから象限Iへの水平移動
4. **ファインチューニング + ガードレール**: 左下から右中への移動（暗黙的知識の制御強化）
5. **マルチモーダル + 形式論理 = Physical AI**: 象限IVから象限Iへの垂直移動

---

## この地図から読み取れること

1. **グラウンディングの成熟度**: 左下（軽量スタート）から右上（デジタル統治）への移動は、組織のAIグラウンディング成熟度を表す
2. **コストと効果のトレードオフ**: 右上に行くほど効果は高いが、コストと複雑性も増大する
3. **ハイブリッド化の必然性**: 単一の手法では象限Iに到達できない。複数手法の合成（Graph RAG = KG + RAG等）が右上への移動の鍵
4. **形式性の壁**: 象限III→象限IIへの移動（形式性の向上）は、専門知識と投資が必要。LLMによるオントロジー自動構築がこの障壁を下げつつある
5. **結合度の壁**: 象限II→象限Iへの移動（運用統合）は、インフラ投資とDevOps/MLOps能力が必要
